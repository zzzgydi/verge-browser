# Security Policy

## Supported Versions

This project is pre-1.0. Maintainers apply security fixes to the latest `main` branch.

## Reporting a Vulnerability

Report suspected vulnerabilities privately. A public issue can expose users before a fix is available.

Report security issues privately to the maintainers with:

- a clear description of the issue
- reproduction steps or a proof of concept
- affected endpoints, routes, or runtime components
- impact assessment if known

This repository does not list a dedicated security contact.

1. If available, open a draft GitHub security advisory.
2. If advisories are unavailable, contact a maintainer through a private channel.
3. Include the information listed above.

## Disclosure Expectations

Before publishing details, give maintainers time to assess and fix the issue.
